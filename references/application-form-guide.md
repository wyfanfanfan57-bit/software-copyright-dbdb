# 在线申请表填写内容生成（复制粘贴用 Markdown）

## 1. 何时生成

标准时机：**两份鉴别材料 PDF（code.pdf、手册 PDF）导出并核对完成后，由助手主动询问使用者
是否需要**，得到肯定答复后再生成；开工时不主动询问。使用者在任意时刻直接要求（如“帮我填
软著申请表”“生成申请表填写内容”“给我能复制粘贴的内容”）也立即生成。
它是**第三份交付物**：手册 docx、code.docx 讲“软件是什么”，本文件讲“在线表单每个框里填什么”。

**在线页面截图是可选项，不是生成前提**：

- 提供截图：按截图中当期实际字段、单选项与字数上限逐一对齐，最精确；
- 不提供截图：按本文件第 4 节内置的标准字段清单与常见上限直接生成，并在 MD 顶部加粗提示
  使用者“提交前对照在线页面逐字段核对字段名称与字数上限”；表单若有出入，以页面为准调整。

## 2. 产物与形式

- 文件名：`软著申请表填写内容_<软件全称>_<版本号>.md`，放入用户指定的输出目录。
- 按在线系统的步骤页组织（软件申请信息 → 软件开发信息 → 软件功能与特点 → 鉴别材料）。
- 每个文本字段给一个**可整段复制的代码块**；单选项写明“点选哪个按钮”；上传项写明传哪个 PDF。
- 每个字段标注页面字数上限，并在交付前实测字数（见第 5 节）。
- 截图未覆盖的页面（著作权人身份、日期、联系方式等）单列“需用户本人确认/补充”清单，不要代填。

## 3. 事实采集：以实际为准，禁止编造

| 字段 | 事实来源与取法 |
|---|---|
| 软件全称、版本号 | 与两份 docx 页眉逐字一致；版本号用标准格式 `V数字`（如 V1.0、V1.0.1） |
| 软件简称 | 无简称则**留空**，不要填“无” |
| 权利取得方式 / 权利范围 | 自研默认“原始取得 / 全部权利”；继受取得、部分权利必须由用户明确说明 |
| 源程序量（行） | 对用户确认的提交范围（入口文件 + 主体源码包，排除 tests、工具脚本、打包配置、虚拟环境、模型、数据等）**实测物理行数**，与 code.docx 范围一致 |
| 开发硬件环境、开发操作系统 | 以**实际开发机**为准；Windows 可用 `Get-CimInstance Win32_Processor`、`Win32_ComputerSystem`（内存）、`Win32_OperatingSystem` 实测，不得臆造 CPU/内存 |
| 运行硬件环境、运行平台 | 取自操作手册“运行环境”章节的真实最低/建议配置 |
| 开发环境/开发工具、编程语言、支撑环境 | 取自 requirements.txt / pyproject / 打包配置 / 手册，版本号照实；本地数据库、可选模型等按实际写 |
| 开发目的、面向领域、主要功能、技术特点 | 只写材料中**真实存在**的功能与技术，逐条可溯源；不扩写、不夸大、不虚构 |
| 技术特点标签 | 按软件真实技术属性勾选（如本地 AI 推理可选“人工智能软件”）；拿不准可不选标签、只填文字说明 |
| 著作权人身份信息、开发完成日期、首次发表日期、联系方式 | 材料/截图中没有就留**醒目占位**由用户填写；日期不得用手册编写日期代替法定完成/发表日期 |
| 鉴别材料交存方式 | 默认“一般交存”；仅当用户明确提出保密等需求时才考虑例外交存 |

源程序量实测片段（按确认范围自行改文件清单）：

```python
from pathlib import Path
root = Path(r"<项目根>")
files = [root / "run.py"] + sorted((root / "app").rglob("*.py"))  # 按用户确认的范围
total = 0
for f in files:
    total += len(f.read_text(encoding="utf-8", errors="replace").splitlines())
print(len(files), total)
```

| | 开发该软件的操作系统 | 50 | 实测 |

| | 运行支撑环境/支持软件 | 50 | 数据库、可选运行时、查看软件 |
| | 编程语言 | 标签 + 其他 120 | 勾选对应语言（Python 在“展开更多”） |

| | 开发目的 | 50 | 解决什么问题、实现什么闭环 |
| | 面向领域/行业 | 按页面标注 | 真实行业与业务场景 |
| 软件功能与特点 | 软件的主要功能 | **500–1300** | 分条概述真实功能，一条对应一个功能点 |
| | 软件的技术特点 | 标签 + 100 | 架构、存储、关键技术特点 |
| 程序鉴别材料 | 一般交存 | PDF | code.pdf（前连续 30 页 + 后连续 30 页；全量 ≤60 页传全量） |
| 文档鉴别材料 | 一般交存 | PDF | 操作手册 PDF（不足 60 页按页面要求传全部） |

## 5. 字数自检（交付前必做）

对 MD 中每个代码块实测 `len(文本)`：50 限字段 ≤50、技术特点 ≤100、主要功能落在
500–1300；标点、英文字母、空格均按 1 字符计，并留 1–2 字余量。超限先压缩措辞再交付，
不要让用户到网页上被计数器拦下。

## 7. 闸门

1. 标准流程下先完成两份 PDF，再主动询问、获确认后生成本 MD；不抢先、不默认生成。
2. MD 先生成交用户核对；身份、日期等占位必须由用户本人确认后才能填报。
3. 无截图也可生成，但必须在 MD 顶部提示使用者对照当期在线页面核对字段与字数上限；
   在线页面与本文件不符时，**以页面实时标注为准**，有截图按截图调整后再交付。
