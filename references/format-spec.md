# 内置标准版式规格（软著文档）

> 本规格来自一已授权登记的成功案例（操作手册 + 代码页），是本技能脚本的输出标准。
> 除非申请人明确要求，**不得更改字体、字号、页边距、分节和字段结构**；所有数值已写死在脚本中。

## 1. 通用页面设置

- A4：宽 11906 × 高 16838 twips（210×297mm）。
- 页边距：上 1440、下 1440、左 1800、右 1800 twips（上下 2.54cm，左右 3.17cm）。
- 页眉距边界 850/851、页脚距边界 992 twips。
- 标题颜色必须显式设为黑色 RGB(0,0,0)（避免 Word 主题蓝色）。

> 1 twip = 1/1440 英寸；表格宽度合计约 14.65cm（版心宽度）。

## 2. 手册 docx（软件全称.docx）

### 结构（两节）

1. **第一节**：封面 + 目录（同一节内分页），无页脚页码。
2. **第二节**：正文，页脚居中 PAGE 域，`pgNumType start=1`（正文第 1 页为 1，封面/目录不计页码）。
3. 两节页眉相同：居中 9pt 宋体“软件全称 版本号”，**无横线**。

### 封面（第一节第 1 页）

全部居中、单倍行距，宋体：

- 软件全称标签与名称：26pt（“软件全称：”独占一行，名称另起一行，名称可拆两行）。
- 版本号：26pt，写作“版本号：Vx.x.x”。
- 文档类别：28pt，默认“操作手册”（也可“说明书”等，由 spec.meta.manual_title 决定）。
- 日期：22pt，写作“YYYY年M月D日”。
- 纵向留白参照脚本（标签前 5 空行、版本后 3 空行、类别后 7 空行）。

### 目录（第一节第 2 页，必须恰好 1 页）

- “目录”14pt 居中。
- 条目宋体 12pt：章（一级）顶格；节（二级）左缩进 420 twips。
- 右对齐页码、点导引线（right tab @ 8306 twips，leader=DOTS）。
- 行距为 XML 固定值 20 磅（`w:line=400 lineRule=exact`，段前段后 0），保证 30 条内单页。
- 构建时页码先写占位 0，正文分页测量后由 `patch_toc.py` 回填真实页码。

### 正文样式

| 元素 | 字体（中文/西文） | 字号 | 其他 |
|---|---|---|---|
| 一级标题（章） | 黑体/黑体 | 16pt 加粗 | 居中，段前段后 7.8pt，Heading 1 |
| 二级标题（节） | 宋体/宋体 | 14pt 加粗 | 左对齐，段前段后 6pt，Heading 2 |
| 正文 Normal | 宋体/Calibri | 12pt（小四） | 1.5 倍行距，首行缩进 2 字符，两端对齐 |
| 项目符号 | 同上 | 12pt | 手动“• ”，左缩进 480、悬挂 240 twips，单倍行距 |
| 操作步骤 | 同上 | 12pt | 手动中文数字加点“1．2．3．”，按正文段落排版 |
| 数据表格 | 宋体 | 10.5pt（五号） | Table Grid 灰框，表头加粗居中，行内垂直居中，1.15 倍行距；宽列左对齐 |
| 截图占位框 | 宋体灰字 RGB(0x80,0x80,0x80) | 10.5pt | 1×1 灰色边框表格，高约 5.2cm（可 5.0–5.6），居中提示语 |
| 图题 | 宋体 | 10.5pt | 居中，格式“图X  标题”（图号与标题间两空格） |

### 块类型（spec 中可用）

`para`（普通段落，可 indent:false）、`bullets`（项目符号列表）、`steps`（自动编号）、
`table`（headers/rows/widths）、`figure`（no/title/hint/height_cm，渲染为占位框+图题）。

## 3. 代码页 docx（code.docx）

- **单节**；Normal 宋体五号（sz=21，10.5pt）两端对齐；每一行源码 = 一个段落。
- 段落格式：`spacing after=46 line=210 lineRule=exact`（固定 10.5pt 行距，段后约 2.3pt）。
- run 四套字体（ascii/hAnsi/eastAsia/cs）全部宋体，sz=21、szCs=21；`xml:space=preserve` 保留行首行尾空格。
- **连续行号**：sectPr 内 `<w:lnNumType countBy=1 restart=continuous/>`，配合 `docGrid linePitch=312`；
  满页约 54–58 个行号（自动折行占行但续行不显示行号，属正常）。
- 页眉 9pt 宋体：居中软件名+版本、右侧 PAGE 域、段落底部 single sz4 横线；页脚留空。
- tab 位：居中 4153 twips、右对齐 8306 twips。
- PAGE 域必须是完整五段结构：fldChar begin → instrText ` PAGE ` → separate → 缓存结果“1” → end。

### 60 页规则（版权中心常见要求：前连续 30 页 + 后连续 30 页，每页不少于 50 行）

1. 先构建全量文档，WPS 重分页测总页数 N。
2. 二分查找：front_end = 恰好填满第 30 页的段落数；back_start = 第 N-29 页首段索引。
3. 重建为“前 30 页正文 + 分页符 + 后 30 页正文”，行号在全文档连续编号。
4. 若全量 ≤ 60 页：直接提交全量（成功案例全量 52 页即如此），不做切分。
5. 末页为源码自然结束（可不满页），其余每页必须 ≥50 个行号，由 `verify_code.py` 机器校验。

## 4. 源码保真红线

- 源码逐字拼接：不改写、不格式化、不删减行内字符；**禁止把 Python 字符串中的英文双引号
  改成中文引号**（word audit 的 E_CHINESE_ASCII_DOUBLE_QUOTE 对代码页是误报，必须忽略）。
- 含 TAB 的源码行需先在项目内统一为空格缩进，否则构建器报错退出（TAB 会导致代码页错位）。
- 文件拼接顺序：入口脚本（run.py/main.py）→ 各包（__init__ 优先，其余字母序），
  可在 files.txt 中手工调整；默认排除 .venv、venv、__pycache__、build、dist、tests 等目录。
